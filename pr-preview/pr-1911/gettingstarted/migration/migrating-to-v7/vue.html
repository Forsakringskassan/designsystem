FCrudButton

Komponenten FCrudButton är borttagen.

För enskilda knappar använder du FButton. När du placerar tabellen i FCrudDataset kopplar du menyåtgärdernas onClick till updateItem(item) och deleteItem(item), som du når via en template ref på FCrudDataset. Utanför tabeller får du samma funktioner som slot-props i defaultslotten.

Så ersätter du propsen:

  • action ersätts med updateItem(item) eller deleteItem(item) i menyåtgärdens onClick eller knappens @click.
  • icon anges på en action i menu-kolumnen eller med icon-left på FButton.
  • label anges med actionens label eller som knappens text i FButton.

-    <template #default>
+    <template #default="{ updateItem, deleteItem }">
         <f-list :items>
             <template #default="{ item }">
-                <f-crud-button action="modify" :item icon>
+                <f-button
+                    icon-left="pen"
+                    size="small"
+                    variant="tertiary"
+                    @click="updateItem(item)"
+                >
                     Ändra {{ item.name }}
-                </f-crud-button>

FTable

I FKUI v7 har egenskapen text bytt namn till screenreaderText för tabellkolumner av typen "button" och "menu" i FTable. Ändringen förtydligar att strängen som returneras endast används som tillgänglighetstext för skärmläsare och inte visas visuellt i cellen.

Sammanfattning av ändringar

Migrering av kolumndefinitioner

Uppdatera samtliga kolumner med type: "button" eller type: "menu" i defineTableColumns genom att byta ut text mot screenreaderText:

 const columns = defineTableColumns<Row>([
     {
         type: "button",
         header: "Button",
         description: "Column 4",
         key: "button",
         icon: "trashcan",
-        text(row) {
+        screenreaderText(row) {
             return row.button;
         },
     },
     {
         type: "menu",
         header: "Actions",
-        text() {
+        screenreaderText() {
             return "Actions";
         },
         actions: [{ label: "foo" }, { label: "bar" }],
     },
 ]);
🤖 Prompt för AI Agenter

Search the codebase for defineTableColumns and column objects containing type: "button" or type: "menu". Rename text to screenreaderText on matching column objects. Run TypeScript type-checking (tsc) to verify no remaining type errors exist.

Datamängder useDatasetRef

Det metadata-baserade datamängds-API:et är borttaget. Det omfattar typen Dataset<T>, typerna DatasetArrayMetadata och DatasetElementMetadata samt funktionerna useDatasetRef(), datasetIterator() och getDatasetMetadata().

Använd vanliga arrayer eller Vue-refar i stället för useDatasetRef().

-const rows = useDatasetRef<Row>(initialRows);
+const rows = ref<Row[]>(initialRows);

För nästlade tabellrader anger du egenskapen med expandable-attribute:

-const rows = useDatasetRef<Row>(initialRows, "children");
+const rows = ref<Row[]>(initialRows);

-<f-table :rows :columns></f-table>
+<f-table :rows :columns expandable-attribute="children"></f-table>

Den relaterade funktionen removeDatasetRows() är också borttagen. Ersätt den med removeTableRows(). Ange expandableAttribute när rader ska kunna tas bort från nästlade arrayer:

-removeDatasetRows(rows, row);
+removeTableRows(rows, row, "children");
🤖 Prompt för AI Agenter

Sök igenom applikationen efter Dataset<T>, DatasetArrayMetadata, DatasetElementMetadata, useDatasetRef(), datasetIterator(), getDatasetMetadata() och removeDatasetRows().

Migrera till vanliga arrayer eller Vue-refar. Använd ref<T[]>(...) när raderna behöver vara reaktiva och en vanlig array när de inte ändras. Ta bort beroenden av datasetmetadata och uppdatera importer och typannoteringar. För nästlade rader i FTable, ange egenskapen med expandable-attribute. Ersätt removeDatasetRows() med removeTableRows() och ange egenskapen för nästlade rader när det behövs. Om befintlig funktionalitet använder metadata för att visa positioner, beräkna positionen utifrån applikationens data och bevara den avsedda presentationen.

FCrudDataset

FCrudDataset öppnar inte längre några modaler själv. Istället anropas onCreate, onUpdate och onDelete med en callback commit som applikationen anropar när åtgärden ska genomföras. Applikationen ansvarar för att öppna modaler, till exempel med formModal() och confirmModal().

Följande har tagits bort:

  • Slottarna #add, #modify och #delete.
  • Propparna beforeCreate, beforeSubmit, beforeValidation, onCancel, addNewModalHeader, modifyModalHeader, deleteModalHeader och formModalSize. Motsvarande värden skickas istället direkt till modalerna.
  • Eventen created, updated och deleted. Applikationen vet själv när den anropar commit.
  • Enumen Operation (ADD, DELETE, MODIFY, NONE). Använd istället de åtgärdsspecifika callbackarna onCreate, onUpdate och onDelete, eftersom varje callback redan motsvarar en åtgärd.
  • Textnycklarna för modalernas rubriker och knappar (fkui.crud-dataset.modal.*). Det finns inga standardtexter längre, så applikationen behöver själv ange knapptexterna. För samma beteende som tidigare: "Lägg till" och "Avbryt" när en rad läggs till, "Spara" och "Avbryt" när en rad ändras samt "Ja, ta bort" och "Nej, avbryt" när en rad tas bort.
  • Metoderna cancelButton(), confirmButton() och egenskapen form från FCrudDatasetPageObject samt cancelButton() och confirmButton() från FCrudDatasetSelectors. Använd FModalPageObject eller FModalSelectors istället.
  • ActivateItemInjected() och typerna ActivateItemInterface och ActivateItemCallback. En egen komponent som presenterar raderna använder istället useCrudDatasetPresenter() med afterCreate, handleDelete och nestedKey. handleDelete(item, commit) ersätter registerCallbackBeforeItemDelete och måste anropa commit() synkront.

Knappen "Lägg till ny" visas när onCreate är satt (tidigare när slotten #add fanns).

Innehållet kan läggas direkt i FCrudDataset, <template #default> behövs inte längre.

onCreate, onUpdate och onDelete kan vara asynkrona. Om en callback returnerar ett promise som avvisas rapporteras felet till app.config.errorHandler.

-<f-crud-dataset v-model="rows" :before-create @created="save">
-    <template #default> ... </template>
-    <template #add="{ item }">
-        <f-text-field v-model="item.name"> Namn </f-text-field>
-    </template>
-    <template #delete="{ item }"> Vill du ta bort {{ item.name }}? </template>
-</f-crud-dataset>
+<f-crud-dataset v-model="rows" :on-create :on-delete>
+    ...
+</f-crud-dataset>

function save(row: Row): void {
    // save implementation
}

async function onCreate(commit: FCrudDatasetCommitCreate<Row>): Promise<void> {
    try {
        const row = await formModal<Row>(MyRowModal, {
            props: { row: { name: "" } },
        });
        save(row);
        commit(row);
    } catch {
        /* användaren avbröt */
    }
}

async function onDelete(
    row: Row,
    commit: FCrudDatasetCommitDelete,
): Promise<void> {
    const confirmed = await confirmModal({
        heading: "Är du säker på att du vill ta bort raden?",
        content: `Vill du ta bort ${row.name}?`,
        confirm: "Ja, ta bort",
        dismiss: "Nej, avbryt",
    });
    if (confirmed) {
        commit();
    }
}

Innehållet från slottarna #add och #modify flyttas till en egen modalkomponent baserad på FFormModal (se Modal API only). onUpdate får en kopia av objektet, så originalet lämnas orört om användaren avbryter. Skicka det ändrade objektet till commit().

🤖 Prompt för AI Agenter

För varje användning av FCrudDataset:

  1. Flytta innehållet i slottarna #add och #modify till en ny komponent som använder FFormModal med propparna isOpen, value och vidarebefordrar close-eventet.
  2. Lägg till onCreate(commit) som öppnar modalen med formModal() från useModal(), med objektet som tidigare returnerades av beforeCreate, och anropar commit(item) med resultatet. Fånga avbrott (formModal() avvisar promise när användaren avbryter).
  3. Lägg till onUpdate(item, commit) på motsvarande sätt och anropa commit(modified). item är redan en kopia, så den behöver inte klonas.
  4. Ersätt slotten #delete med onDelete(item, commit) som öppnar confirmModal() och anropar commit() om användaren bekräftar. Använd tidigare deleteModalHeader som rubrik.
  5. Flytta logik från eventen created, updated och deleted till respektive callback innan commit anropas.
  6. Flytta beforeSubmit, beforeValidation, formModalSize och modalrubriker till modalkomponenten.
  7. Ange knapptexter explicit i modalerna, de har inga standardtexter längre. Använd tidigare standardtexter: "Lägg till"/"Avbryt" för lägg till, "Spara"/"Avbryt" för ändra och "Ja, ta bort"/"Nej, avbryt" (confirm/dismiss i confirmModal()) för ta bort. Sök efter översättningar av textnycklarna fkui.crud-dataset.modal.* i projektet, använd de värdena istället och ta bort nycklarna.
  8. Skicka med ett meddelande för skärmläsare som är specifikt för raden som argumentet alert till commit, till exempel commit(item, `${item.name} har lagts till`), commit(modified, `${modified.name} har ändrats`) och commit(`${item.name} har tagits bort`). Använd ett namn eller annan egenskap som identifierar raden för användaren.
  9. Ersätt FCrudDatasetPageObject.confirmButton()/cancelButton() i tester med new FModalPageObject(".modal").primaryButton()/secondaryButton().
  10. Ta bort importer av Operation från @fkui/vue. Flytta kod som grenar på Operation.ADD, Operation.MODIFY eller Operation.DELETE till onCreate, onUpdate respektive onDelete. Ta bort kod som använder Operation.NONE.

Verifiera resultatet genom att bygga projektet och köra enhetstester.

IPopup

Fokushantering är inte längre aktiv som standard i IPopup. Om popup tidigare använde standardbeteendet, lägg till focus för att fortsätta flytta fokus till det första tabbningsbara elementet när popup öppnas och återställa fokus när den stängs:

-<i-popup :is-open :anchor>
+<i-popup :is-open :anchor focus>

set-focus- och focus-element-proparna är borttagna och ersätts av en gemensam focus-prop. Ta bort :set-focus="false" eftersom avstängd fokushantering nu är standard, och ersätt :set-focus="true" med focus. Ett dynamiskt värde för set-focus kan istället skickas till focus:

-<i-popup :is-open :anchor :set-focus="shouldSetFocus">
+<i-popup :is-open :anchor :focus="shouldSetFocus">

Om du använder focus-element, skicka funktionen till focus istället:

-<i-popup :is-open :anchor :focus-element="getFocusElement">
+<i-popup :is-open :anchor :focus="getFocusElement">

Om båda propar används kan du flytta villkoret till en funktion som returnerar null när fokus inte ska flyttas. Exemplet utgår från att shouldSetFocus är en Vue-ref:

function getPopupFocusElement(): HTMLElement | null {
    return shouldSetFocus.value ? getFocusElement() : null;
}

-<i-popup :is-open :anchor :set-focus="shouldSetFocus" :focus-element="getFocusElement">
+<i-popup :is-open :anchor :focus="getPopupFocusElement">

Du kan också använda ett beräknat värde som returnerar elementet eller null och skicka en funktion som returnerar det värdet till focus. Se då till att det beräknade värdets beroenden är reaktiva.

Om funktionen returnerar null flyttas inte fokus och det återställs inte heller när popup stängs. Om funktionen returnerar ett element flyttas fokus dit och återställs när popup stängs.

keyboard-trap-propen är inte aktiv som standard längre. Om du tidigare använde standardvärdet, lägg till keyboard-trap för att fortsätta hålla tabbfokus inom popupen. Detta gäller även om du hade stängt av fokushanteringen med :set-focus="false". Behåll dynamiska värden för keyboard-trap och låt den vara avstängd där den tidigare var false.

-<i-popup :is-open :anchor>
+<i-popup :is-open :anchor keyboard-trap>

-<i-popup :is-open :anchor :keyboard-trap="false">
+<i-popup :is-open :anchor>
